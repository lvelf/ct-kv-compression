# Analysis plan

The primary outcome is the change in held-out exact-match accuracy after full KV tuning compared with direct ICL for the same ordered demonstrations and the same 200 questions. Boolean outcomes also include how often the model answers True, accuracy for gold True questions, accuracy for gold False questions and the count of invalid outputs. These are sentence-level classification outcomes; a True prediction counts even when the correct answer was False. Accuracy and fraction-predicted-True in the analysis CSVs are on a 0–100 scale when labeled `_pp`. For example, a change of +5 means five percentage points, independent of the starting score.

## Prespecified comparisons

| Question | Comparison | Evidence to look for |
| --- | --- | --- |
| Does label skew contribute to regression? | On Boolean, at fixed shot count, subtract the change under the 50%-True demonstration condition from the change under 20%- or 80%-True. Compare tuned full KV with its own matched ICL first. | Predicted True shifts down more at 20%, up more at 80%, and accuracy on the underrepresented label suffers. Compare both skew directions with balanced demonstrations. Report counterexamples by seed. |
| Can more demonstrations reduce the penalty? | At each label ratio, compare tuned-minus-ICL for nested 20 vs 10 shots. Then compare this shot effect between skewed and balanced conditions. | A consistently smaller accuracy penalty at 20 shots supports a shot-count contribution. Effects may depend on label ratio. Baseline ceiling effects and changes in example identity still matter. |
| Does retaining a smaller prefix change the result? | Compare 25% answer-attention tuning with full tuning in the same seed/shot/ratio/optimizer block. | Less regression at 25% is compatible with compression helping. Its comparison with full ICL includes both selection and tuning. Training capacity, the retained information, and selection are coupled here. |
| When does held-out performance change? | Inspect validation NLL (gold answer tokens), accuracy and predictions after 0, 2, 4, 8 and 16 updates, when present; for a 32-step trajectory also inspect its endpoint. Compare independent prespecified 4/8/32-step endpoints with a 16-step control on the fixed test. | Report the first *observed* validation checkpoint below step 0. Short schedules that preserve test accuracy suggest a useful follow-up on the stopping rule. Each independent horizon has its own cosine LR schedule. |
| Does changing which cache tensors are trainable help? | Key-only and Value-only minus joint KV on identical original demonstrations, full retained prefix, same optimizer seed and 16 updates. | Compare accuracy, True predictions on Boolean, trainable scalars, gradient memory and Adam state. This changes both capacity and tensor identity. A difference alone cannot isolate parameter count. |
| Does attention selection beat random? | Random minus answer-attention at 20 shots and 16 updates, per task/seed/budget, with identical ordered examples, test questions and retained bytes. | A negative accuracy difference favors attention. Each seed has one random mask. Report variation before generalizing. |
| Which stage costs most? | For a fixed task, shot count, mode, budget and update count, inspect initialization, selection, forward, backward, optimizer and per-step time, plus phase-specific memory and peak. | Divide each phase by the corresponding adaptation time. Read residual time as loop overhead. Diagnostic validation time and memory are separately measured. The first-microbatch saved-activation measurement counts unique floating-point storages saved by autograd outside model and prefix storages. Forward live-memory change is a separate allocator-based proxy. Neither quantity measures the global activation peak. |

## How to read the outputs

Run `python analysis.py --root results` from the package folder. It reads only completed runs recognized by the driver. Re-running after more completions updates the CSVs in `results/analysis/`. Use a separate results root for an independent replicate.

- **absolute_by_run.csv** lists per-run outcomes. **condition_summary.csv** reports accuracy, True counts/rates, class accuracy and resource measurements summarized at each condition. All 200 test IDs and the gold answers are verified for paired contrasts.
- **paired_by_seed.csv** contains the paired change inside each demonstration seed. **paired_summary.csv** reports its mean, sample SD and SE across demonstration seeds. With all three seeds, SE = sample SD divided by √3. Both optimizer seeds must finish for a main tuning block; their differences are averaged before pooling demonstration seeds. For partial reports, read `n_demo_seeds` and treat estimates with fewer than three as provisional. A one-seed SE is blank. These SEs quantify variation over sampled demonstrations conditional on this fixed test set; no independence is assumed for repeated test questions. Emphasize the magnitude and direction of effects per seed; the study has only three demonstration seeds.
- **validation_checkpoints.csv** gives the observed within-run validation accuracy (0–1), NLL and counts. **training_loss.csv** gives the training loss after each update. **validation_dynamics.csv** identifies the earliest sampled validation decline and the step with the lowest validation loss, earliest if tied. Ten validation questions give accuracy 10-point increments. An interim decline can disappear by the next checkpoint.
- **validation_horizon_selection.csv** compares a prespecified rule with fixed 16 on the unchanged test set. Within the original 10-shot task/seed, pick the shortest of the 4, 8, 16 and 32-step schedules achieving minimum *final validation NLL* (ties go to fewer updates). **validation_horizon_association.csv** provides an exploratory within-seed Spearman correlation between final validation NLL and test accuracy at those four horizons. It requires all four schedules. A consistent negative association supports further validation of loss as a stopping signal. This is retrospective schedule selection: running all four schedules consumes more compute than running any one. It does not measure the savings of a deployed, prospective stopping rule.
- **resource_profiles.csv** lists run-level scalars and CUDA allocator snapshots in bytes, and synchronized timings in seconds. Peak allocated memory differs from total GPU use in nvidia-smi. Adam state bytes and GPU-resident Adam state bytes are reported separately. Training with frequent validation incurs overhead even though its measurements are excluded from adaptation.
- **historical_checks.csv** compares aligned original 11/24 ICL endpoints and repeated tuned controls using ordered demo and test-ID hashes. Earlier runs are reference observations; all formal run counts refer to new jobs. The original order differs from the new stratified main experiment, which has its own ICL control.
- Inspect `results/runs/<id>/predictions.jsonl` to see per-question outputs. For any “degradation” conclusion, check both class-specific accuracies and score direction in all three seeds. Report date-understanding results separately because the output is a multiple-choice option. Keep validation-based decisions separate from the final 200-question test, which is reused for paired comparisons and has been examined in prior studies.
